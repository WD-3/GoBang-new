【问题根源分析 / Root Cause Analysis】
--------------------------------------------------------------------------------

经过深入测试，发现问题的真正原因：

1. ✅ Temperature 参数正确传递到 Ollama API
2. ✅ 代码层面没有问题
3. ❌ 但模型输出仍然相同

**根本原因**:
- gemma3:1b (1B 小模型) 对 Temperature 不敏感
- Prompt 中包含了示例坐标"H8"，模型在模仿
- 简单 prompt 导致模型认为只有一个"正确"答案

**测试证据**:
```
Temperature 0.1 (5 次): H8, H8, H8, H8, H8  ← 完全相同
Temperature 0.9 (5 次): H8, H8, H8, H8, H8  ← 完全相同
```

【推荐解决方案 / Recommended Solutions】
--------------------------------------------------------------------------------

方案 A: 使用更大的模型（推荐）⭐⭐⭐⭐⭐
----------------------------------------
gemma3:1b 只有 1B 参数，对 Temperature 不敏感。
建议使用 4B 或更大模型：

| 模型 | 参数 | Temperature 响应 | 推荐度 |
|------|------|-----------------|--------|
| gemma3:1b | 1B | ❌ 差 | 不推荐 |
| qwen3-4b | 4B | ✅ 中等 | 推荐 |
| qwen3-8b | 8B | ✅✅ 好 | 强烈推荐 |

测试命令:
```bash
# 查看可用模型
ollama list

# 拉取更大的模型
ollama pull qwen3:4b
ollama pull qwen3:8b
```

方案 B: 提高 Temperature 到 0.8-1.0 ⭐⭐⭐
----------------------------------------
如果只能用 1B 模型，建议：
- Temperature 设置为 0.8-1.0
- 增加随机性
- 接受一定的"乱下"

方案 C: 添加思维链（Chain of Thought）⭐⭐⭐⭐
----------------------------------------
修改 prompt，让模型先思考再落子：

```
先分析局势，然后输出坐标：
1. 检查是否有四连
2. 检查对手是否有四连
3. 检查是否有活三
4. 选择最佳位置

思考：[模型思考过程]
落子：[坐标]
```

优点：模型更深入思考，更有"棋感"
缺点：输出变长，需要解析

方案 D: 使用传统 AI 算法 ⭐⭐⭐⭐
----------------------------------------
对于研究目的，建议使用 Minimax 或 MCTS：

```bash
# 使用 AI 对战（不是 LLM）
gobang cli new -b ai -w ai --algorithm minimax --depth 4
```

优点：
- 完全可控
- 可复现
- 有明确的评估函数

缺点：
- 不是"智能"下棋
- 缺少 LLM 的创造性

【技术总结 / Technical Summary】
--------------------------------------------------------------------------------

本次修复涉及的关键点:

1. Temperature 参数传递链:
   网页滑块 → fetch请求 → Flask API → _setup_llm_players → 
   create_llm_player → OllamaClient → Ollama API

   局结束 → fetch DELETE → api_delete_game →

   - 取决于模型大小
   - 取决于 Prompt 设计
