【问题诊断 / Problem Diagnosis】
--------------------------------------------------------------------------------

用户反馈：循环对战的每一局仍然一模一样，棋子位置毫无变化。

经过深入测试，发现根本原因：
1. gemma3:1b (1B 参数) 模型太小，对 Temperature 不敏感
2. 即使设置 Temperature=0.8 和 seed=-1，模型仍倾向于输出最可能的 token
3. Prompt 中的示例和结构可能导致模型产生"锚定效应"

测试证据：
- Temperature 0.8 测试 5 次：H7, H7, H6, H7, H7 (只有 2 种变化)
- 实际对战 3 局：G7, G7, G7 (完全相同)

【实施的修复 / Implemented Fixes】
--------------------------------------------------------------------------------

✅ 修复 1: 添加 seed=-1 强制随机性
   文件：gobang/llm_player.py
   位置：OllamaClient.generate 和 OpenAICompatibleClient.generate
   修改内容:
   - 在 API payload 中添加 "seed": -1
   - 告诉 Ollama 不要使用固定种子
   
   代码:
   ```python
   "options": {
       "temperature": kwargs.get("temperature", self.temperature),
       "seed": -1,  # 强制随机性
       "num_predict": kwargs.get("max_tokens", 300),
   }
   ```

✅ 修复 2: 增加 num_predict 到 300
   文件：gobang/llm_player.py
   修改内容:
   - 从 100 增加到 300
   - 给思维链足够的输出空间

✅ 修复 3: 添加随机偏移到 Prompt
   文件：gobang/llm_player.py
   位置：LLMPlayer.__init__ 和 _build_prompt
   修改内容:
   - 每个 LLMPlayer 实例生成随机偏移 (1-10000)
   - 在 Prompt 中添加随机种子提示
   
   代码:
   ```python
   self.random_offset = random.randint(1, 10000)
   random_seed = f"\n【随机种子/Random Seed】{self.random_offset} - 请根据此种子做出不同选择\n"
   ```

✅ 修复 4: 候选点随机打乱
   文件：gobang/llm_player.py
   位置：_get_candidates 方法
   修改内容:
   - 在返回候选点前随机打乱顺序
   - 避免模型总是选择第一个候选点
   
   代码:
   ```python
   import random
   random.shuffle(candidates)
   return candidates[:10]
   ```

✅ 修复 5: 回退逻辑随机化
   文件：gobang/llm_player.py
   位置：_get_fallback_move 方法
   修改内容:
   - 如果 LLM 失败，随机选择候选点
   - 而不是总是选择中心点
   
   代码:
   ```python
   random.shuffle(candidates)
   return candidates[0]
   ```

✅ 修复 6: 强化 Prompt 随机性提示
   文件：gobang/llm_player.py
   修改内容:
   - 添加"重要提醒"部分
   - 明确要求不要重复之前的走法
   - 要求有多个选择时随机选择

【多层随机性保障 / Multi-Layer Randomness Guarantee】
--------------------------------------------------------------------------------

现在系统有 5 层随机性保障：

层级 1: API 层面
- seed=-1 告诉 Ollama 使用随机种子
- Temperature=0.8 增加输出多样性

层级 2: Prompt 层面
- 随机偏移 (1-10000) 确保每次 Prompt 不同
- 明确要求随机选择

层级 3: 候选点层面
- 候选点随机打乱
- 避免模型锚定效应

层级 4: 回退层面
- LLM 失败时随机选择
- 不总是选中心点

层级 5: 工程层面
- 每局游戏独立创建 LLM 玩家
- 游戏结束后清理状态

【故障排查 / Troubleshooting】

- 或者忽略此错误，其他随机性措施仍然有效

【技术总结 / Technical Summary】
--------------------------------------------------------------------------------

本次修复的核心思想：
"不要依赖单一随机性来源，建立多层保障"

即使某一层失效（如模型对 Temperature 不敏感），
其他层仍然能提供随机性（如候选点打乱、随机偏移）。

这种"防御性编程"确保在各种情况下都能有一定程度的随机性。
